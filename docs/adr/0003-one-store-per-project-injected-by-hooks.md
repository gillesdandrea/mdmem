# One store per project, injected by hooks, saved through MCP

> Superseded in part by [ADR 0005](0005-home-store-by-default-local-store-on-purpose.md): the store is `~/.mdmem/<key>/` by default and `.mdmem/` at the root only on purpose; outside git the working directory is the project, with no walk-up. The wiring and the MCP write path stand.

> Superseded in part by [ADR 0004](0004-two-wiring-scopes-store-on-first-save.md): the consequences on wiring as committed project files and on Codex's per-project server describe the project scope only, and Codex's global hook gave way to a hook per scope (amended 2026-10-26); the global scope wires the agent's user-wide files and creates the store on the first save.

A project has one memory store, a real `.memory/` directory at the repository's root: the parent of the git common dir, or a bare repository's own directory. Every worktree and subdirectory resolves to it, a submodule uses its superproject's, and without git it is the first `.memory/` above the working directory. Each supported agent (Claude Code, IBM Bob, Codex CLI) is wired the same way: session-start hooks run `mdmem` to inject the memory protocol and the index, and the agent saves through the mdmem MCP server. In a project using mdmem, Claude Code's own auto memory is turned off, and its existing memories are imported once.

We chose this over sharing the store through Claude Code's auto-memory directory, in either direction. Pointing Claude at `.memory/` with `autoMemoryDirectory` needs an absolute path in a gitignored per-checkout file, so every new worktree falls back to Claude's private directory. Linking Claude's directory to `.memory/` makes Claude ask permission for every save through the link. Linking `.memory` to Claude's directory leaves Codex unable to write through the link, with its file tools or the mdmem CLI alike, because its sandbox covers child processes and checks the resolved path (all tested 2026-10-17 with Claude Code 2.1.302 and Codex 0.160). The deeper cause holds in every design: an agent in a linked worktree writes outside its workspace. The MCP server runs outside the agents' sandboxes, so it is the one write path that works everywhere; once every agent needs it, Claude's native memory adds only coupling to `~/.claude`.

## Consequences

- Claude Code's wiring is files committed with the repository: `autoMemoryEnabled: false`, the hook entries and the mdmem tool permission in `.claude/settings.json`, the server in `.mcp.json`. Bob's is `.bob/settings.json` and `.bob/mcp.json`. Codex's hook is global (`~/.codex/hooks.json`, approved once, silent outside a project with a store and in a work tree whose `.codex/config.toml` does not register the mdmem server), because Codex pins hook approval to the hook file's absolute path; its MCP server is registered per project in `.codex/config.toml`.
- Codex's own memory (`[features] memories`, under `~/.codex/memories/`) stays on beside mdmem (amended 2026-10-25): `mdmem enable codex` leaves `features.memories` alone, imports nothing from it, and the check reports nothing about it. Codex writes that memory itself after each session, as summaries of its sessions and tasks, so it does not compete with the store; Claude Code's auto memory does, because it holds facts the agent saves deliberately in the store's own format, and so it is turned off. Turning Codex's off would cost Codex its continuity and gain mdmem nothing. The memory protocol tells every agent whose harness keeps a memory of its own to keep there what is about itself and its sessions, and to save everything about the project, how to work in it and what the user wants to the store.
- Anyone working in the repository needs `mdmem` on PATH, or the hooks and the server fail; a failed session-start hook does not block the agent.
- Only agents with session-start hooks are supported. There is no `AGENTS.md` block and no fallback when hooks do not run (untrusted folder, hooks off); `mdmem status` reports it.
- Claude Code caps one hook entry's context at about 10,000 characters, so the protocol and the index are two entries, the protocol stays under that size, and the index's limit is about 9,500 characters.
- `.memory/` is a real directory and normally not committed; mdmem never edits `.gitignore`. Committing suits projects without worktrees, since each worktree would check out its own copy.
