# Core refuses or degrades; a surface never crashes

mdmem's core signals two kinds of trouble and nothing else. A **refusal** is an operation that would damage the store or lose someone's work: a memory with bad frontmatter or a secret, a write to the index's path, a write or delete against a version the caller has not seen. Core raises it as a typed error that names what to do next (merge the current content, shorten the description, pass `--force`), and each surface catches it once: the CLI prints one line and exits 1, MCP returns an `isError` result that carries the current content on a version conflict. A **degradation** is everything else, chiefly one broken memory among many: the operation does what it can and the problem travels as a warning on the result (a write that landed but left the index stale, a search that answers from the memories that parse). The one thing a broken memory blocks is regenerating the index, because an index that silently drops a memory is worse than a stale one with a warning.

We chose this over "never throw" (every operation returning a result union) because a refusal is not a partial success and must not be ignorable, and over "fail fast everywhere" because an agent must not be locked out of its memory by one bad file. No stack trace ever reaches a user or an agent.
